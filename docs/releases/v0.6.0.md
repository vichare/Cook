# Cook v0.6.0

Cook v0.6.0 adds least-privilege post-publication content moderation, deterministic intent-first recommendations, shareable automatic-refresh recommendation URLs, and accessible ingredient Move menus.

## Highlights

- Content moderation separates author publication intent from platform restriction state. Restricted content disappears from every non-owner public surface while owners retain edit and appeal access.
- Moderator access uses an explicit capability, host-issued one-time claim codes, Passkey step-up, self-review denial, bounded immutable evidence, optimistic idempotent actions, and a PII-free append-only audit ledger.
- `intent-v2` applies scope, must-use, and excluded ingredients as hard filters; desired matches form the first partition, with owned, saved, and favorite-account recipes preferred over other public recipes.
- Recommendation controls use versioned `rv=1` URL state, 250 ms automatic refresh, request cancellation and generation guards, browser Back/Forward restoration, safe canonical-ID downgrade for shared links, and failure-preserving retry.
- Ingredient chips can move atomically among desired, must-use, and excluded buckets through a keyboard- and touch-accessible menu with capacity, URL-size, focus, live-region, viewport, and stale-dialog safeguards.
- Recipe group and alternative `sortOrder` values remain explicit and legacy v1 recipe/import schemas remain accepted for compatible single-ingredient recipes.

## Database and rollback compatibility

Migration `0017_content_moderation.sql` upgrades populated v0.5 databases without changing author intent. Existing public recipes become public + clear + unreviewed; private recipes remain private + clear. The effective legacy `visibility` field remains protected by database triggers and the shared `public_eligible_recipes` view.

Before the first restriction, deployment rollback may restore the matching pre-upgrade database backup and prior image. The first successful restriction writes `release_compatibility.minimum_release = v0.6.0`; after that marker exists, `deploy/upgrade.sh` refuses older binaries. Operators must restore a matching database backup and application release together rather than bypassing the guard.

## Not included

This release does not include a separately scoped bulk importer, drag-and-drop or within-bucket recommendation ordering, or a system-wide ingredient alias catalog. Existing Skill batch guidance remains deterministic per-item processing and does not grant new server capabilities.

## Manual release gates

The remaining human-only gates are the assistive-technology/device checks, measured contrast and production-scale performance checks in `docs/accessibility-release-checklist.md`, plus real-account OTP, Passkey, authenticated image, moderation, and restore smoke tests that cannot be safely automated without production credentials or state.
